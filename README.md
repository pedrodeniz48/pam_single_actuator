# Single PAM Simulation in MuJoCo

Minimal simulation of a **Pneumatic Artificial Muscle (PAM)** using MuJoCo and a Python implementation of a Hill-type muscle model.

The objective of this project is to provide a simple and reproducible environment for studying the dynamics, parameter identification, and control of a single artificial muscle without requiring the complete multi-DOF `pam_mujoco` software stack.

The muscle model is based on the Hill-type formulation presented by **Haeufle et al. (2014)** and follows the open-source implementation provided by the Max Planck Institute for Intelligent Systems' `pam_models` / `pam_mujoco` software.

---

## 1. Overview

The simulation consists of two main components:

1. **Hill-type muscle model**
   Computes the force generated by the artificial muscle according to its activation, length, velocity, and internal contractile-element state.

2. **MuJoCo mechanical simulation**
   Simulates the motion of a mass actuated by the muscle force.

The basic simulation loop is:

```text
Pressure
   │
   ▼
Pressure → Activation mapping
   │
   ▼
Activation a
   │
   │     MTC length / velocity
   │          ▲
   ▼          │
┌─────────────────────┐
│   Hill-type muscle  │
│        model        │
└─────────────────────┘
   │             │
   │ Force       │ dL_CE/dt
   ▼             ▼
 MuJoCo      CE internal state
 dynamics       integration
   │
   ▼
Position / velocity
   │
   └──────────────► new MTC length / velocity
```

At the current development stage, experiments can also command **activation directly**, bypassing the pressure-to-activation mapping.

# 2. Hill-Type Muscle Model

The model follows the Hill-type muscle formulation described by:

> D. F. B. Haeufle, M. Günther, A. Bayer, and S. Schmitt,
> “Hill-type muscle model with serial damping and eccentric force–velocity relation,”
> *Journal of Biomechanics*, vol. 47, no. 6, pp. 1531–1536, 2014.
> DOI: `10.1016/j.jbiomech.2014.02.009`

The model contains four components:

```text
CE  = Contractile Element
PEE = Parallel Elastic Element
SEE = Serial Elastic Element
SDE = Serial Damping Element
```

Conceptually:

```text
                ┌──── PEE ────┐
                │             │
MTC ── SEE/SDE ─┤             ├── MTC
                │             │
                └──── CE ─────┘
```

### Contractile Element (CE)

Represents the active force-producing component of the muscle.

Its behavior depends on:

* muscle activation,
* contractile-element length,
* force-length relationship,
* force-velocity relationship,
* concentric/eccentric contraction.

### Parallel Elastic Element (PEE)

Represents passive elastic behavior acting in parallel with the contractile element.

Below its slack length it generates no force. Above that length, passive force increases nonlinearly.

### Serial Elastic Element (SEE)

Represents elasticity in series with the muscle.

Its force depends on the extension of the serial elastic structure and contains nonlinear and linear regions.

### Serial Damping Element (SDE)

Introduces velocity-dependent damping into the series structure.

This is one of the important extensions of the Haeufle et al. model compared with simpler three-element Hill models.

# 3. Model Inputs and Outputs

The core Hill model can be represented as:

```text
(l_MTC, dot_l_MTC, a, l_CE)
              │
              ▼
        Hill muscle model
              │
              ▼
      (F_MTU, dot_l_CE)
```

## Inputs

### `l_MTC`

Muscle-tendon-complex (MTC) length change relative to the reference configuration.

Unit:

```text
m
```

### `dot_l_MTC`

MTC contraction/extension velocity.

Unit:

```text
m/s
```

### `a`

Muscle activation.

Approximately:

```text
0 ≤ a ≤ 1
```

In `pam_mujoco`, pressure commands are converted into activation before being supplied to the Hill model.

### `l_CE`

Internal state representing the contractile-element length change relative to its initialized equilibrium length.

Unit:

```text
m
```

---

## Outputs

### `F_MTU`

Force generated by the complete muscle-tendon unit.

Unit:

```text
N
```

This force is applied to the MuJoCo mechanical system.

### `dot_l_CE`

Rate of change of the internal contractile-element state.

Unit:

```text
m/s
```

The state evolves according to:

```text
l_CE(k+1) = l_CE(k) + dot_l_CE * dt
```

In the original `pam_mujoco` implementation, MuJoCo maintains this internal state. In this minimal Python implementation, the state is currently integrated explicitly.

# 4. Pressure and Activation

The Hill model itself receives **activation**, not pneumatic pressure.

The original `pam_mujoco` pressure controller performs a linear mapping:

```text
            p - p_min
a = a_min + ----------- (a_max - a_min)
            p_max-p_min
```

where:

```text
p      = commanded pressure
p_min  = minimum pressure
p_max  = maximum pressure

a      = muscle activation
a_min  = minimum activation
a_max  = maximum activation
```

The reference `pam_mujoco` configuration uses approximately:

```text
a_min = 0.001
a_max = 1.0
```

Therefore, it is important to distinguish between two interfaces.

### Muscle-model interface

```text
activation + muscle state
        ↓
    Hill model
        ↓
      force
```

### Complete PAM-system interface

```text
pressure
    ↓
activation
    ↓
muscle dynamics
    ↓
force
    ↓
mechanical dynamics
    ↓
position / velocity
```

For control-oriented experiments, the latter representation is usually the more relevant one.

# 5. MuJoCo Simulation

MuJoCo is used to simulate the mechanical dynamics surrounding the artificial muscle.

The current environment contains:

* one fixed support,
* one vertically moving mass,
* one prismatic joint,
* one tendon connecting the support and moving body,
* tendon-length and tendon-velocity sensors,
* joint-position and joint-velocity sensors.

The model is located at:

```text
models/single_pam.xml
```

The simulation timestep is currently:

```text
dt = 0.002 s
```

corresponding to:

```text
500 Hz
```

---

# 6. Coupling the Muscle Model to MuJoCo

At every simulation timestep, MuJoCo provides:

```text
tendon length
tendon velocity
```

The initial tendon length is recorded:

```python
initial_tendon_length = ...
```

and the MTC displacement supplied to the Hill model is:

```python
delta_l_mtc = tendon_length - initial_tendon_length
```

The muscle model then computes:

```text
F_MTU
dot_l_CE
```

The internal CE state is updated and the resulting muscle force is applied to the MuJoCo system.

Therefore, the numerical simulation forms a feedback loop:

```text
MuJoCo state
     ↓
MTC length + velocity
     ↓
Hill muscle model
     ↓
muscle force
     ↓
MuJoCo dynamics
     ↓
new state
     ↓
    ...
```

# 7. Model Parameters

The muscle parameters are stored in:

```text
config/hill.json
```

The configuration originates from the `pam_configuration` project associated with the Intelligent Soft Robots PAM software.

The parameters are divided into four groups:

```json
{
    "contractile": {},
    "parallel_elastic": {},
    "serial_damping": {},
    "serial_elastic": {},
    "length": 0.68
}
```

Examples include:

```text
f_max       Maximum CE force
l_CEopt     Optimal CE length

a_rel0
b_rel0      Force-velocity parameters

L
v
F           Parallel elastic parameters

d_se
r_se        Serial damping parameters

l
delta_u_nll
delta_u_l
delta_f     Serial elastic parameters
```

These parameters are particularly important for future **parameter-identification experiments**.

# 11. Main Scientific Reference

**Haeufle, D. F. B., Günther, M., Bayer, A., & Schmitt, S. (2014).**

Journal of Biomechanics, 47(6), 1531–1536.

DOI:

`10.1016/j.jbiomech.2014.02.009`

This paper should be the starting point for understanding:

* Hill-type muscle modeling,
* contractile-element dynamics,
* force-length relationships,
* force-velocity relationships,
* concentric and eccentric contraction,
* series elasticity,
* parallel elasticity,
* serial damping,
* internal-state initialization.

**Important:** the original paper models biological muscle. The use of this formulation as an artificial-muscle/PAM model comes from the `pam_models` implementation used by the Intelligent Soft Robots software stack.

# 15. Important Implementation Notes

This project is a **minimal independent Python implementation inspired by and ported from the open-source PAM software**, rather than a direct installation of the complete `pam_mujoco` framework.

This distinction is intentional.

The complete PAM software includes infrastructure for:

```text
multi-DOF robots
agonist/antagonist muscle pairs
pressure interfaces
o80 communication
shared memory
robot control
MuJoCo environments
```

For the current research problem, only the dynamics of a single artificial muscle are required.

The minimal simulator therefore attempts to preserve the relevant Hill-model equations while avoiding infrastructure unrelated to the experiment.

Before using the simulator as the basis for quantitative scientific conclusions, the Python implementation should be numerically validated against the original C++ `pam_models` implementation.
